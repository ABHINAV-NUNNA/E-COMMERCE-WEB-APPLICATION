01 / Java architecture

Proposed: Spring Boot REST controllers → Bean Validation DTOs → service layer → Spring Data JPA → MySQL. Add Spring Security, OAuth2/OIDC clients, a WebAuthn server library, Flyway migrations, centralized exception handling, and structured audit events. Separate CUSTOMER, SELLER, and ADMIN authorization on the server—not merely in the navigation.

Customer scope: browsing, cart, server-priced checkout, private order history, and verified-purchase reviews. Seller scope: business profile, application status, company products, inventory, orders, and sales analytics. Admin scope: seller approval, company verification, reported listings, product moderation, and audit-log review. None of these restricted dashboards is active in this public demo.

02 / Account and security design

Implement registration and login on the separately deployed Java server. Hash passwords using Argon2 or BCrypt. Verify email or SMS with short-lived, single-use, rate-limited challenges; store only a protected challenge digest, never a plaintext OTP. Provide expiration, resend limits, generic error messages, forgot-password tokens with short expiry, account verification status, lockout safeguards, logout, and session-expiry handling.

Offer Google and Microsoft through server-configured OAuth2/OIDC authorization-code flows with state and PKCE. A Google-associated passkey is a separate WebAuthn credential: the browser/authenticator holds the private key. The backend stores credential ID, public key, sign count, user ID, and timestamps only. Verify origin, challenge, relying-party ID, user presence, and signature server-side. Prefer Secure, HttpOnly, SameSite session cookies; enforce CSRF protection, precise CORS origins, TLS, validation, and audit logging. Never place tokens or client secrets in this page.

03 / MySQL schema blueprint — edit for your deployment

Suggested tables: users, roles, user_roles, otp_verifications, oauth_accounts, passkeys, companies, company_products, seller_profiles, seller_applications, products, categories, carts, orders, payments, and audit_logs. Add order items, inventory reservations, reviews, and listing reports in production. The following is illustrative migration material, not a complete production migration. 

CREATE TABLE users (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  email VARCHAR(254) NOT NULL UNIQUE,
  password_hash VARCHAR(255) NULL,
  verified_at TIMESTAMP NULL,
  locked_until TIMESTAMP NULL,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE roles (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(20) NOT NULL UNIQUE
);
CREATE TABLE user_roles (
  user_id BIGINT NOT NULL, role_id BIGINT NOT NULL,
  PRIMARY KEY (user_id, role_id),
  FOREIGN KEY (user_id) REFERENCES users(id),
  FOREIGN KEY (role_id) REFERENCES roles(id)
);
CREATE TABLE companies (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(120) NOT NULL,
  category VARCHAR(80) NOT NULL,
  verified_at TIMESTAMP NULL
);
CREATE TABLE categories (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(80) NOT NULL UNIQUE
);
CREATE TABLE products (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  company_id BIGINT NOT NULL,
  category_id BIGINT NOT NULL,
  name VARCHAR(160) NOT NULL,
  price_minor BIGINT NOT NULL,
  stock INT NOT NULL DEFAULT 0,
  rating DECIMAL(3,2) NULL,
  FOREIGN KEY (company_id) REFERENCES companies(id),
  FOREIGN KEY (category_id) REFERENCES categories(id),
  CHECK (price_minor >= 0),
  CHECK (stock >= 0)
);
CREATE INDEX idx_products_discovery
  ON products(category_id, price_minor, stock);
CREATE INDEX idx_products_company ON products(company_id);

SELECT p.id, p.name, p.price_minor, c.name AS company
FROM products p JOIN companies c ON c.id = p.company_id
WHERE p.category_id = :category_id AND p.stock > 0
ORDER BY p.price_minor ASC LIMIT :limit OFFSET :offset;

05 / README · connect the real stack

  1. Create a Spring Boot app with Web, Security, Validation, Data JPA, OAuth2 Client, MySQL driver, and Flyway.
  2. Implement migrations, DTOs, services, authorization policies, and integration tests.
  3. Replace local catalogue data with authenticated API requests; keep server-side pricing and inventory checks. Use object storage for product images.
  4. Configure an email/SMS provider for OTP delivery and Google/Microsoft OAuth apps on the server. Register WebAuthn relying-party settings and trusted origins.
  5. Integrate a sandbox payment provider through the backend; verify signed webhooks before marking an order paid. Keep payout configuration in the compliant provider dashboard.

Server-only placeholders: SPRING_DATASOURCE_URL, SPRING_DATASOURCE_USERNAME, SPRING_DATASOURCE_PASSWORD, GOOGLE_CLIENT_SECRET, MICROSOFT_CLIENT_SECRET, OTP_PROVIDER_KEY, PAYMENT_GATEWAY_KEY, PAYMENT_WEBHOOK_SECRET, and IMAGE_STORAGE_BUCKET.

06 / Test checklist

  • Registration validation, duplicate email, verification status, OTP expiry, reuse and rate limits, password reset, account lockout, logout, and expired sessions.
  • Google/Microsoft callback cancellation, state mismatch and provider errors; passkey registration, challenge expiry, origin/RP checks, login and sign-count handling.
  • CUSTOMER/SELLER/ADMIN access control and cross-account ownership checks.
  • SQL migration and constraints; search filters; seller approval; inventory races and order totals.
  • Payment sandbox failures, duplicate events and webhook signature verification; security regression, mobile, keyboard and accessibility tests.

07 / Deployment checklist

  • Set environment variables in a secrets manager; never commit production credentials.
  • Use HTTPS and configure frontend/API domains, precise CORS origins, CSRF policy, secure cookies, OAuth redirect URIs and WebAuthn relying-party ID.
  • Run reviewed database migrations, backups and restore tests; configure monitoring, audit retention, rate limiting and incident alerts.
  • Set image storage permissions and verified webhook endpoints. Configure payment and payout details only with the provider.

A domain, Java API, OAuth apps, SMS provider and payment gateway are not provisioned by this portfolio page.
